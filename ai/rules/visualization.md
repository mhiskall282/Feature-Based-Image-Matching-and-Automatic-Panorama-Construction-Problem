# Rules: Visualization Output Standards

## Status
These rules govern all visualization outputs. They are **mandatory** for all figures generated by `src/visualization/draw.py`.

---

## RULE-VIZ01: Every Figure Must Have a Title

Every figure must include:
- A descriptive title (using `plt.title()` or `plt.suptitle()`)
- The method name (SIFT, ORB, or comparison label)
- The experiment name or image pair identifier
- Any relevant metric count (e.g., "N=127 keypoints", "84 inliers (62.2%)")

**Prohibited**: Saving a figure without a title.

---

## RULE-VIZ02: All Figures Must Be Saved at Minimum 150 DPI

```python
plt.savefig(outpath, dpi=150, bbox_inches='tight')
```

For figures intended for the final report, use 200 DPI and save copies to `outputs/report_figures/`.

**Prohibited**: `dpi=72` or any resolution below 100.

---

## RULE-VIZ03: No Interactive Blocking in Experiment Scripts

Do not call `plt.show()` in experiment scripts. It blocks execution and prevents automation.

```python
# In experiment scripts — ONLY save:
plt.savefig(outpath, dpi=150, bbox_inches='tight')
plt.close()  # Important: release memory

# In interactive notebooks or development sessions — show is acceptable
```

---

## RULE-VIZ04: Always Convert BGR to RGB Before Matplotlib Display

```python
# Correct
plt.imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))

# FORBIDDEN — shows incorrect colours
plt.imshow(img)  # img is BGR from cv2.imread
```

**Every** `plt.imshow()` call on an OpenCV-loaded image must include the conversion.

---

## RULE-VIZ05: Colour Conventions Are Fixed

Use these colours consistently across all figures:

```python
COLOURS = {
    'sift_keypoints':     '#2196F3',  # Blue
    'orb_keypoints':      '#FF9800',  # Orange
    'raw_match_lines':    (0, 0, 255),     # Red (BGR for cv2.drawMatches)
    'inlier_match_lines': (0, 255, 0),     # Green (BGR)
    'outlier_match_lines':(0, 0, 255),     # Red (BGR)
    'sift_bars':          '#2196F3',  # Blue (for bar charts)
    'orb_bars':           '#FF9800',  # Orange (for bar charts)
}
```

**Prohibited**: Using the default matplotlib colour cycle, which assigns random colours across different figures.

---

## RULE-VIZ06: Figures Must Close After Saving

```python
plt.savefig(outpath, dpi=150, bbox_inches='tight')
plt.close()  # REQUIRED — prevents memory accumulation across many experiment runs
```

When running hundreds of experiment trials, each `plt.figure()` that is not closed will leak memory. `plt.close()` is mandatory after every `plt.savefig()`.

---

## RULE-VIZ07: Output Directory Must Exist Before Saving

```python
from pathlib import Path

output_path = Path(outpath)
output_path.parent.mkdir(parents=True, exist_ok=True)
plt.savefig(output_path, dpi=150, bbox_inches='tight')
```

Never assume the output directory already exists. Always create it.

---

## RULE-VIZ08: Match Visualizations Must Limit Display Count

When `len(matches)` is very large (> 200), limit the number drawn for clarity:

```python
MAX_DISPLAY_MATCHES = 150

display_matches = matches[:MAX_DISPLAY_MATCHES] if len(matches) > MAX_DISPLAY_MATCHES else matches

img_matches = cv2.drawMatches(
    img1, kp1, img2, kp2, display_matches, None,
    flags=cv2.DrawMatchesFlags_NOT_DRAW_SINGLE_POINTS
)
plt.title(f"{len(matches)} matches (showing {len(display_matches)})")
```

**Required**: Always include the total match count in the title even when only a subset is displayed.

---

## RULE-VIZ09: Rich Keypoint Drawing for Keypoint Visualizations

Use `cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS` for keypoint visualizations:

```python
img_kp = cv2.drawKeypoints(
    gray, keypoints, None,
    flags=cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS
)
```

This draws circles sized to the keypoint scale with an orientation line — far more informative than simple dots. **Prohibited**: Drawing keypoints as plain dots when the method provides scale and orientation information.

---

## RULE-VIZ10: Before/After RANSAC Must Use Consistent Layout

The before/after RANSAC comparison must always be:
- **Two panels side by side** (left = before, right = after)
- **Red lines** for before-RANSAC matches
- **Green lines** for after-RANSAC inliers
- Match count in each panel title
- Inlier ratio as a percentage in the after-panel title

---

## RULE-VIZ11: Output Filenames Must Follow the Convention

```
outputs/{experiment}/{method}/
├── input_images.png
├── preprocessed_{img_name}.png
├── keypoints_{method}_{img_name}.png
├── raw_matches_{method}_{pair_id}.png
├── before_after_ransac_{method}_{pair_id}.png
├── warped_{method}_{pair_id}.png
├── panorama_{method}.png
└── failures/
    └── failure_{code}_{pair_id}.png
```

**Prohibited**: Ad hoc, undocumented filenames like `result_final2.png` or `test_output.png`.

---

## RULE-VIZ12: Comparison Figures Must Label Methods Clearly

For any figure that shows results from multiple methods on the same axes:
- Use the colour convention (blue = SIFT, orange = ORB)
- Include a legend
- Include the method name in axis tick labels or panel titles

**Prohibited**: Figures comparing methods with labels like "Method A" and "Method B" without specifying which is which.

---

## RULE-VIZ13: Axis Labels on All Charts

Every `matplotlib` Axes with quantitative data must have:
- x-axis label (`ax.set_xlabel(...)`)
- y-axis label (`ax.set_ylabel(...)`)

Images displayed with `imshow` are exempt from axis labels but must have titles.
