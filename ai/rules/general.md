# Rules: General — Binding Project Rules

## Status
These rules are **mandatory**. Deviating from them requires explicit written justification in the commit message or implementation notes. They override any convenience preference.

---

## RULE-G01: Read the AI Workspace First

Before writing any code or running any experiment, the implementing agent or developer MUST:
1. Read `/ai/README.md`
2. Read `/ai/context/project-overview.md`
3. Read `/ai/context/examination-requirements.md`
4. Identify which skills are relevant to the current task
5. Read those skills before proceeding

**Violation**: Writing code without reading the relevant skills and context documents.

---

## RULE-G02: Requirement Traceability is Mandatory

Every significant code component must include a comment referencing the requirement ID it satisfies.

```python
def apply_ransac(...):
    """
    # REQ-07: Apply RANSAC to eliminate incorrect correspondences
    # REQ-08: Estimate the homography matrix
    """
```

If a function does not map to any examination requirement, it is either a utility function (acceptable) or unnecessary complexity (remove it).

---

## RULE-G03: No Monolithic Files

The project must use a modular architecture as specified in `/ai/context/expected-deliverables.md`.

**Prohibited**: A single `main.py` that contains detection, matching, RANSAC, warping, stitching, evaluation, and visualization all in one file.

**Required**: Separate modules for each major pipeline stage, importable independently.

---

## RULE-G04: No Black-Box Pipeline APIs

The following is **prohibited**:

```python
# FORBIDDEN — hides the entire pipeline
stitcher = cv2.Stitcher_create()
status, panorama = stitcher.stitch(images)
```

The following is **required**:
- Explicit feature detection
- Explicit descriptor computation
- Explicit matching
- Explicit RANSAC
- Explicit homography estimation
- Explicit warping
- Explicit compositing

OpenCV primitives (e.g., `cv2.SIFT_create()`, `cv2.findHomography()`, `cv2.warpPerspective()`) are permitted and encouraged. The pipeline they form must be explicit.

---

## RULE-G05: No Pretrained Deep Learning Models

This project must use classical feature-based methods as studied in CSCD608. The following are **prohibited**:
- SuperPoint, SuperGlue, LoFTR, D2-Net, DELF, or any deep feature extractor
- YOLO, ResNet, VGG, or any recognition model
- Any model loaded from a `.pth`, `.onnx`, or `.tflite` file

The central pipeline must be explainable from first principles without invoking neural network internals.

---

## RULE-G06: No Fabricated Results

**Absolutely prohibited**:
- Typing in keypoint counts that were not measured
- Copying results from a paper and presenting them as your own
- Rounding "2 inliers" up to "150 inliers" because the algorithm performed poorly
- Generating a synthetic panorama and claiming it came from the actual images

**All reported numbers must come from `print()` statements or CSV files generated by the actual running pipeline.**

---

## RULE-G07: All Experiments Must Be Runnable

Every experiment must be executable with a single command:
```
python experiments/run_baseline.py
python experiments/run_rotation.py
# etc.
```

The experiment runner must load images from the specified data directory, run the full pipeline, save results to CSV, and save visualizations. No manual steps in the middle.

---

## RULE-G08: Git History Must Be Clean

- Commit working, self-contained units of functionality
- Do not commit files with syntax errors or that crash on import
- Do not commit large binary files unless specifically needed (use `.gitignore` for outputs)
- Write meaningful commit messages referencing the pipeline stage and requirement

---

## RULE-G09: Environment Must Be Documented

Before running the project on a clean machine, the only setup needed should be:
```
pip install -r requirements.txt
```
No undocumented manual installation steps, no hardcoded absolute paths, no assumed environment variables.

---

## RULE-G10: Intermediate Results Must Be Preserved

Every pipeline stage must save its outputs before the next stage runs. This enables:
- Debugging individual stages without re-running the full pipeline
- Re-running only the evaluation step without repeating feature detection
- Reproducibility verification

Intermediate outputs to preserve:
- Detected keypoints (as images)
- Descriptor arrays (as `.npy` files, optionally)
- Raw match lists (as images and/or pickle files)
- RANSAC inlier masks
- Homography matrices (as text files)
- Warped images

---

## RULE-G11: Document Every Parameter Choice

For every non-default parameter, include a comment explaining the choice:
```python
sift = cv2.SIFT_create(
    contrastThreshold=0.03,  # Lowered from default 0.04 to detect more keypoints
                              # in low-texture indoor scene (baseline experiment)
)
```
```python
RANSAC_THRESHOLD = 5.0  # 5 pixel reprojection threshold — standard choice for
                          # 640x480 images; validated against baseline inlier ratio
```

---

## RULE-G12: Never Modify the /ai Directory During Implementation

The `/ai` directory is the specification, not the implementation. Do not:
- Delete or overwrite skills or rules during implementation
- Add implementation code to the skills files
- Modify the requirements traceability to retroactively match a different implementation

If the specification needs to change, create a new version and document why.
