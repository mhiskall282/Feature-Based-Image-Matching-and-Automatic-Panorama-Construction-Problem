# Skill: Academic Reporting

## Overview

This skill guides the preparation of the academic report for this examination project. The report must demonstrate not only that the system works but that the student understands *why* it works, how the algorithms were selected and tuned, what the results mean, and where the system fails.

**This skill does NOT write the report** — it provides structure, guidance, and constraints for writing it honestly and rigorously.

---

## Report Requirements Summary

The report must contain all sections listed in `/ai/context/expected-deliverables.md` §4. Key properties:

- **All results are experimentally measured** — no fabricated numbers
- **All figures are generated by the code** — no hand-drawn diagrams
- **All claims are supported by evidence** — cite experiments, figures, or tables
- **All failures are documented** — not hidden
- **All references are real** — no fabricated citations
- **Written at MPhil/MSc level** — precise, technical, and well-argued

## Section-by-Section Guidance

### Abstract (200–300 words)
Write last. Summarise:
- What problem was solved (panorama construction)
- Methods used (SIFT, ORB, RANSAC)
- Key quantitative findings (best inlier ratio, processing time comparison)
- Key conclusions and limitations

### §1 Introduction
- Define the panorama problem clearly
- State the objectives of the project
- Briefly preview the pipeline and methods
- Include a high-level pipeline diagram (generated by code)
- **Do not** overclaim — state what this project does, not what computer vision can do in general

### §2 Literature Review
- Cover: Harris corners (1988), SIFT (2004), ORB (2011), RANSAC (1981), homography estimation, image stitching (Brown & Lowe 2007)
- For each method: explain the core idea, not just copy the abstract
- Discuss why these methods are appropriate for this task
- **Do not** cite papers you have not read — only cite what you can explain
- Typical length: 1.5–3 pages

### §3 Dataset / Image Acquisition
- Describe your scene: what it is, why it was chosen, why it is appropriate
- Describe capture method: device, how many images, approximate overlap
- Include a figure showing all input images
- If synthetic images were generated for stress tests, explain how
- **Do not** claim you captured images that you did not

### §4 Image Preparation
- State every preprocessing step: grayscale conversion, resizing, equalization
- Justify each choice: "Grayscale conversion was performed because SIFT and ORB operate on single-channel intensity images (cv2.COLOR_BGR2GRAY)"
- Show figures of before/after for any significant preprocessing
- State the resulting image dimensions

### §5 Feature Detection
- Describe SIFT detection: DoG scale space, extrema detection, keypoint refinement
- Describe ORB detection: FAST, Harris scoring, orientation assignment
- Show keypoint visualizations for both methods on the same image
- Report keypoint counts in a table
- Discuss the spatial distribution observed (is it uniform? clustered?)

### §6 Feature Description
- Describe SIFT descriptor: 128-dim float, gradient orientation histograms, invariances
- Describe ORB descriptor: rBRIEF, binary, intensity comparisons, Hamming distance
- Explicitly state distance metrics and why each is appropriate
- **Justify the incompatibility of L2 with binary descriptors** — show you understand this

### §7 Feature Matching
- Describe BFMatcher, Lowe's ratio test (for SIFT), cross-check (for ORB)
- Show initial correspondence figures for both methods
- Report match counts before and after filtering
- Discuss match quality visually

### §8 RANSAC
- Explain RANSAC algorithm precisely: minimum sample, model fitting, inlier counting, iteration
- State parameters used (reprojection threshold, confidence, max iterations) and justify
- Show before/after RANSAC comparison figures
- Report inlier counts and ratios in a table

### §9 Homography Estimation
- Explain what the homography matrix encodes (projective transformation, 8 DOF)
- State when homography is valid (planar scene or pure rotation)
- Show the estimated H matrix for at least one image pair
- Discuss the corner verification result
- Explain why 4 point pairs are the minimum

### §10 Image Warping
- Explain warpPerspective: inverse mapping, bilinear interpolation
- Explain canvas size computation (bounding box of all mapped corners)
- Show warped image figures alongside reference
- Discuss any visible distortion

### §11 Panorama Construction
- Explain multi-image strategy (reference-based or sequential)
- Describe compositing method (simple overwrite or alpha blending)
- Show final panorama for both methods
- Discuss visible quality differences between SIFT and ORB panoramas

### §12 Experimental Design
- Describe the 4 stress experiments and rationale
- State the controlled variable for each experiment
- State what was held constant across experiments
- State the metric used to measure performance

### §13 Quantitative Results
- Present the full results table from `results/comparison_table.csv`
- All 6 required metrics (keypoints, initial matches, RANSAC inliers, inlier ratio, time, panorama quality)
- **This table must be generated from actual measurements — never typed manually**

### §14 Algorithm Comparison
Write a structured comparison of SIFT vs ORB:

```
Table: SIFT vs ORB — Properties

Property             | SIFT              | ORB
---------------------|-------------------|------------------
Detection method     | DoG extrema       | FAST + Harris
Descriptor type      | 128-dim float32   | 256-bit binary
Distance metric      | L2 (Euclidean)    | Hamming
Rotation invariant   | Yes               | Yes (limited)
Scale invariant      | Yes               | Partial
Illumination robust  | Better            | Less robust
Speed (detection)    | [measured]        | [measured]
Speed (total)        | [measured]        | [measured]
Keypoints (baseline) | [measured]        | [measured]
Inlier ratio (base)  | [measured]        | [measured]
```

Discuss the trade-offs: when would you prefer ORB over SIFT and vice versa?

### §15–18 Stress Experiments

For each experiment (Rotation, Scale, Viewpoint, Illumination):
- State the conditions tested
- Show a results table for that experiment
- Show the line plot (metric vs condition level)
- Discuss the trend: does performance degrade? How quickly? At what threshold?
- Compare SIFT vs ORB behaviour

### §19 Failure Analysis
See `/ai/skills/failure-analysis.md` for full guidance.

### §20 Limitations
Be honest about what the system cannot do:
- Limited to approximately planar scenes / pure rotation
- Performance degrades under extreme conditions
- No real-time capability (processing time)
- Simple blending produces visible seam artefacts
- No handling of moving objects
- Tested on limited dataset

### §21 Discussion
Interpret the results beyond just describing them:
- What do the inlier ratio differences tell us about the descriptor invariances?
- Is the faster ORB method worth the accuracy trade-off for this task?
- How do the stress experiment results confirm or contradict the theoretical properties of the algorithms?

### §22 Conclusion
- Briefly restate objectives and summarise what was achieved
- State the key finding (which method performed better under which conditions)
- Note the most important limitation

### §23 Future Work
Genuine, specific suggestions:
- Multi-band blending for better panorama quality
- Bundle adjustment for lower reprojection error across N images
- Exposure compensation before stitching
- Extending to 3D scenes (depth estimation, SfM)
- Deep feature extractors comparison (with the caveat that this changes the nature of the problem)

### References
Use a consistent citation style (IEEE or APA). Only cite papers you have actually engaged with. Include:
- Lowe (2004) — SIFT
- Rublee et al. (2011) — ORB
- Fischler & Bolles (1981) — RANSAC
- Brown & Lowe (2007) — panorama stitching
- Harris & Stephens (1988) — corners
- Hartley & Zisserman (2004) — MVG textbook
- Szeliski (2022) — CV textbook

## Writing Quality Standards

- **Passive voice where appropriate**: "The homography was estimated using RANSAC" (not "We RANSAC'd the thing")
- **Present tense for describing the system**: "The detector finds DoG extrema..."
- **Past tense for describing what you did**: "Experiments were conducted on three overlapping images..."
- **Avoid vague language**: Not "SIFT is better" but "SIFT achieved a higher inlier ratio (0.72) compared to ORB (0.51) under the 30° rotation condition"
- **Every numerical claim must have a source**: "...as shown in Table 3" or "...measured in Experiment A"

---

## Anti-Patterns to Avoid in the Report

- ❌ "The algorithm performed well" — quantify it
- ❌ "As expected, SIFT outperformed ORB" — show the data; don't assume
- ❌ "According to [Author, Year]..." when you've only read the abstract
- ❌ Showing a figure without referring to it in the text
- ❌ Presenting a results table that differs from what the code actually outputs
- ❌ "The system achieved 100% matching accuracy" — no system does this
- ❌ Copy-pasting the examination question text as your problem definition
